# 轨迹引擎审查与验收报告（v1.2.3）

日期：2026-09-06 · 工具：`cmd/trajlab`（纯 Go，全程不依赖浏览器）

## 一、审查结论：修了什么

用平台对全矩阵跑门禁（修前 vs 修后），确认并修复了 3 个生成算法缺陷 + 1 个调优：

### 缺陷 1：段装饰用"时间占比"当"长度"用（主缺陷，之前人工审计发现）

弓形（bow）和低频游走的幅度基准 `sd` 原来取 `总距离 × 该段的时间占比`——但时间占比在
"首段时长占比被钳到 0.5~0.72 并重分配"之后，和各段实际弦长严重脱节。修前 800px 三段式
（f1=0.65）实测各段弦长约 520 / 80 / 200px，而装饰基准却是 176 / 264 / 352px：

- 首段大摆动（实际 520px，基准 176）→ 弓形被压小 2~3 倍，摆动太直；
- **慢速区矫正段（实际 80px，基准 264）→ 弓形被放大 3 倍，最大侧偏达弦长 40%+，
  视觉上是一个明显的"钩子"**；
- 末段同样放大 ~2 倍。

修法：装饰移到最终时间分配之后，`sd` 用每段**实际弦长**（相邻端点直线距离）。

### 缺陷 2：路径点偏移恒为一侧（机器签名）

两段/三段路径的中间路点偏移 `randn(lo,hi)` 是"恒正"的均匀分布，导致所有路径都朝同
一侧（行进方向顺时针侧）鼓包——真人不会有这种系统性偏侧。修法：偏移量级不变，符号
随机（`±randn`）。修后全矩阵 "右鼓包占比" 稳定在 0.5±噪声。

### 缺陷 3：段交界处游走不连续（平台发现的新缺陷）

每段的低频游走相位独立采样，而游走项在段末不为零 → 每个交界处路径侧跳 1~3px；
当采样间隔恰好落在交界前几十微秒时，位置差/极小间隔会在指标里造出 35000px/s 的
假速度尖峰（污染峰速、峰值时刻、段检测）。修法：整个侧向偏移（弓形+游走）乘以
`sin(πs)` 包络，段两端归零，交界天然连续。

### 调优 4：矫正段更直

文献里矫正子运动（homing）接近直线。首段保留 3~12% 弦长弓形，矫正段系数下调为
2~7%。修后全矩阵最大段侧偏比 ≤ 0.14（门禁 0.18 + 4px 下限）。

## 二、验收平台与门禁

`trajlab analyze` 在 23 档距离（10~2200px，覆盖 1920×1080 对角）× 8 方向 × N 次
的矩阵上生成路径并逐条打分。门禁（生成路径必须全部满足）：

| 门禁 | 标准 | 含义 |
|---|---|---|
| arc_chord | 1.00~1.18（<100px 时 1.40） | 总绕路程度像人 |
| seg_lateral | 每段侧偏 ≤ max(0.18×弦长, 4px) | 无慢速区钩子（缺陷 1 的回归门） |
| t2p | 峰值时刻 0.15~0.60（<25px 豁免） | 峰速位置在移动中前段 |
| duration | 0.75~1.30 × Fitts 基线 | 时长守律 |
| submoves | <70px 1 段；70~420 2 段；≥420 2~3 段 | 结构随距离正确切换 |
| seg_detect | 检出段 = 计划段（±1） | 计划结构真实落到路径上 |
| backtrack | ≤ 1.5% 样本倒退 | 无反向抽搐 |
| end_err | ≤ 0.5px | 精确落点 |
| jump | 单步 ≤ 15000px/s | 无传送式跳变 |
| peak_ratio | 峰/均 1.2~3.8 | 速度集中度合理 |
| sign_balance | 单元级：|平均不对称度| 与右鼓包占比在 √n 自适应 4σ 带内 | 无系统性偏侧（缺陷 2 的回归门） |

### 修前 / 修后对比

- 修前（5 距离 × 2 方向 × 12 次的小矩阵，120 条）：**65/120 条失败**。
  失败集中在 seg_lateral（800px 单元 5/12 超限，实测侧偏 7~32px）、seg_detect、
  假尖峰导致的 jump/peak_ratio/t2p。
- 修后全矩阵（23 × 8 × 24 = **4416 条**）：**0/4416 失败，PASS**。
  关键指标：弧/弦 1.001~1.066；最大段侧偏比 ≤ 0.144；时长/Fitts 恰为 0.80~1.25
  （随机化设计值）；峰值时刻 0.23~0.30（长距）/0.45~0.59（短距）；峰/均 ≤ 3.37。
- 回归测试：`go test ./internal/trajlab/` 里的 `TestGeneratorPassesGates`、
  `TestNoDirectionalSignature` 常驻守护，80 连跑稳定。

数据文件：`docs/trajlab-report-v1.2.3.json` / `.txt`（本报告对应的全矩阵原始结果）。

## 三、真人轨迹录制（record）

    trajlab record -dists 500,600 -angles 0,90 -count 3

流程（全自动起止，前后静止不入库）：

1. 屏幕覆盖层标出绿圈（起点）红圈（终点），光标自动放到起点；
2. 按 Enter，提示音后开始移动（什么时候动无所谓，检测器等起手）；
3. 速度 ≥60px/s 持续 40ms 判定起手，速度 <25px/s 持续 250ms 判定停手
   （600ms 宽限内再动视为犹豫，继续记录）；
4. 前后静止段裁掉，慢速减速滑入保留，存为一条 JSON。

- 每条轨迹一个文件：`d0500_a090_001.json`（距离_方向_序号）；
- 固定目录 `~/.mouse-bridge/trajectories`，整文件夹可拷到别的机器直接用；
- 建议按 50px 网格录（50/100/150/…），每个距离可配多个方向（水平/垂直/两条对角线），
  同一 (距离,方向) 可录多条作回放时的抽样池。

## 四、置信度选择与回放

- `trajlab pick -dist 500 -angle 0 -tol 30`：库里有 470~530px 的真人轨迹 → 选中
  并给出置信度（距离越近、方向越合越高）；没有 → 置信度 0，回退算法生成。
  方向不匹配没关系——`Rescale` 会把真人轨迹旋转+等比缩放放到目标几何上，动力学不变。
- `trajlab replay -dist 500 -angle 0`（或 `-file xxx.json`，可 `-to-dist/-to-angle/-start`
  重标定）：3 秒倒计时后按真人轨迹的时间戳逐点回放。

## 五、自检

`trajlab selftest` 用引擎自身驱动光标走一段已知路径，端到端验证
轮询→起停检测→裁剪→指标→入库（**会移动真实光标约 1 秒**）。
